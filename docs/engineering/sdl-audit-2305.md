## Enumeration coverage and limits

Existing `CONNECTION_GRANT_SCOPES` registration already covers `Mutation.createConnectionGrant`. The new `PROCESS_CREDENTIAL_PROVIDERS` registration is coordinate-scoped to `Mutation.createAiServiceConfig`, isolates only the semicolon-terminated promised list, and derives membership from `Object.keys(AI_PROVIDER_ENDPOINTS).filter(usesProcessCredential(..., 'HADRON_SERVER'))`. Neither a provider elsewhere in that block nor ordinary unrelated provider prose supplies list membership. This is the conditional subset the runtime accepts, not every known provider.

Closed role sets are per-Agent data, not a platform enum; no static checker can establish their contents. Status examples are explicitly partial examples. Owner-level walk order is a precedence algorithm, not a set-completeness promise. Other access, refusal order, TTL, bounds, encryption, graph locks, history and downstream UI/retention claims require manual code review or behavioral tests; this audit does not present the enumeration gate as proof of them.

Red-first evidence: two new omission controls failed with 30 passing tests before registration (after generating this checkout's Prisma client; an earlier missing-client cleanup error is discarded). Registered predicate + corrected descriptions: 32/32 tests pass. The second control retains omitted provider names outside the promised list, so a broad text search cannot make it pass. Complete-list and unrelated-coordinate controls pass. Live SDL omission controls and description-stripped topology comparison are recorded with final validation in the PR.

QA shape: SDL checks plus independent read-through per T1/scoped §10. No stack, full suite, production access, browser or external provider call is needed or claimed. Umbrella #1246 remains open; the later supplemental population still needs its own allocation.
