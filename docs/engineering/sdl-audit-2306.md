## What can and cannot be automated

No new exported closed-vocabulary registry is present in these 13 descriptions. Reference dispatch and audit authority are branch predicates; allowed ID shapes are regexes; decision codes are an unbounded prefix/base26 algorithm; refusal examples are scattered path-specific errors, not a complete shared constant. Calendar constraints live in a downstream tool. Adding a copied list would create the second source of truth this audit is meant to avoid. Consequently this slice adds **no checker registry entry** and makes no omission-mutation claim for a new list. Existing S1/S2/S5 registrations remain intact.

The six URN resource kinds in effectiveAccess are manually compared with resolveResource's switch (memory/node/app/agent/org/user), with the bare-id config branch separately checked; runtime ResourceKind is a TypeScript union, not an exported enumerable dispatch registry. resolveUrn's access prose is deliberately not a closed enumeration of all possible future kinds. Numeric/name/config/liveness bounds, authority, concealment and ordering require code tracing or focused behavioral tests; passing SDL guards does not prove them.

Calendar follow-up: verify exactly-one boundary and zone/offset rejection against the actual deployed calendar-tool implementation before marking the U row verified. No access or deployment grant is inferred from this audit. Historical client-message parity and 'returned once' claims are limited to the inspected server return path, not recoverability from client logging.
