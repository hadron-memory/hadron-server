# Regenerating the skilldoc parity fixtures

`src/lib/skilldoc/__fixtures__/skilldoc-fixtures.json` is **generated by the Go
reference implementation** in hadron-cli. That is what makes the A2 parity gate
meaningful: a port that diverges reds, rather than passing its own restatement
of itself.

Until #1235 the generator lived nowhere — it was written ad hoc, run once, and
thrown away. The fixture's own header said *"Regenerate rather than hand-edit"*
while the thing that regenerates it did not exist, so the only available action
was the one it forbade. `genfix.go` is that program, committed.

## Running it

```bash
# 1. A git ARCHIVE at a named commit — never a colleague's working checkout.
#    Their tree moves while you measure, and a `-dirty` build is not a version.
#    (dev:findings:a-tool-on-path-can-be-a-colleagues-working-build)
#
#    rm -rf, NOT bare `mkdir -p`: extracting a second commit over a surviving
#    tree leaves behind every file the new archive does not contain, so you
#    build a mixture of two revisions and call it one (@codex, PR #1249).
#
#    The commit the checked-in file was LAST generated at, so running this
#    unchanged reproduces it byte for byte (its `sourceCommit` says the same).
#    Move it forward only to a commit whose Go matches the law you pin: an
#    older one regenerates retired rules (@codex, PR #1295).
COMMIT=3582c97
rm -rf /tmp/cli && mkdir -p /tmp/cli
gh api repos/hadron-memory/hadron-cli/tarball/$COMMIT | tar xz -C /tmp/cli --strip-components=1

# 2. The generator must live INSIDE the module — it imports internal/skilldoc.
mkdir -p /tmp/cli/cmd/genfix && cp scripts/skilldoc-fixtures/genfix.go /tmp/cli/cmd/genfix/main.go
(cd /tmp/cli && go build ./cmd/genfix)

# 3. Regenerate from the current fixture. The COMMIT is an argument, so
#    `sourceCommit` records the revision you actually built from rather than
#    whatever the program was last edited to say.
/tmp/cli/genfix src/lib/skilldoc/__fixtures__/skilldoc-fixtures.json "$COMMIT" > /tmp/new.json

# 4. Update the $comment to say which sections moved, then install.
#    Do not skip this: $comment and sourceCommit are the only provenance the
#    file carries, and a wrong one is worse than none.
```

## It is idempotent, and that was not free

Running it twice on its own output produces a byte-identical file. The first
version did not: it APPENDED the added cases unconditionally, so step 3 above —
"regenerate from the current fixture" — would have duplicated them on every
run (measured: 13 → 16 → 19 hash cases). The tests kept passing, because
duplicate case names simply run twice, so the file would have grown silently
for as long as anyone followed this README (@codex, PR #1249). Cases are
upserted by `Name` now; if you add one, give it a name and do not append.

## It preserves fields it has never heard of

Cases are decoded as `map[string]any`, not into a Go struct. A closed struct
silently drops anything it does not declare — which cost **seven `why`
explanations** on the first attempt (the fixture's total went 32 → 25): five
from `hash` and two from `render`, each the one-line reason that case exists
("Go trims NEL, JS does not — the hash diverges if ported naively"). No test
reads `why`, so nothing failed (@codex, PR #1249).

The loss was first reported as **29**, which was a count of DIFF LINES — inflated
by the reformat — in the same breath as a warning that a diff-line count is not
a measurement. Seven is the measured number. Counting the instrument's output
instead of the thing is the mistake this file keeps being about.

## Two couplings that are easy to break

- **`render` and `renderParseRoundTrip` are NAME-ALIGNED.** The round-trip test
  looks its inputs up in `render` by case name, so a case added to one and not
  the other is an undefined lookup — a crash, not a missing assertion. Found
  the hard way on #1235.
- **`renderParseRoundTrip` records what Go READ BACK**, not the raw inputs. Its
  `content` is post-`NormalizeBody`, so computing a digest directly from the
  inputs skips the normalization the section exists to exercise. Also found the
  hard way, one round earlier.

## What it covers, and what it does NOT

`genfix.go` regenerates `hash`, `render`, `renderParseRoundTrip` (stamping
`sourceCommit`); since #1289, `lintCollisions` (stamping
`lintCollisionsSourceCommit`); and since #1292, `declared` (stamping
`declaredSourceCommit`). The `lintCollisions` INPUTS are authored in
`collisionCases()` and upserted by name; `declared` keeps its inputs. Only the
verdicts come from Go, including each `declared` case's `unknown` list
(`UnknownHostKeys`, so the generator needs hadron-cli#679 or later to build).
Also since #1292, `lintUnknownHostKeys` (stamping
`lintUnknownHostKeysSourceCommit`): authored keys chosen for the characters Go's
`%q` and `JSON.stringify` quote differently, so the warning's MESSAGE is pinned
word for word, quoting included.
Since #1315, `lintReserved` (stamping `lintReservedSourceCommit`): nodes
authored in `reservedCases()` that declare Claude's reserved `synced` name, with
findings PER HOST from Go's `LintFor` over every row of its host table
(`findingsByHost`). Not `Lint`: that is the Claude-only wrapper, and with it a
`codexSkill` declaration is never evaluated at all (PR #1343 review). It is a section of its own, not cases upserted into
`lint`, for the reason below. The generator still BUILDS at a commit older than
hadron-cli#712, but Go emits no `skill-name-reserved` there, so the TypeScript
side reds against the result. Use plain spellings in these cases: Go folds with
`x/text/collate` and the server with ICU, and the two differ only on exotic code
points the name grammar already refuses.
Since #1341, `lintMarkup` (stamping `lintMarkupSourceCommit`): the Cowork probe
descriptions, authored in `markupCases()`, with findings per host the same way
as `lintReserved`; it needs hadron-cli#722 or later for the rule to exist.
Since #1323, `parseHeader` (stamping `parseHeaderSourceCommit`): Go's
`ParseFile` over authored edits of ONE Go-rendered file (`headerCases()`: the
`rev=` edge values, and whitespace separators in the current and the legacy
header). Each case records the edited file as `input` beside Go's verdict, so
the TypeScript side re-derives nothing. An edit whose anchor is not unique in
the base file panics rather than editing the wrong spot. It needs hadron-cli#724
(merged as `9e7d2bd`) or later, where `File.Revision` exists.

It does NOT touch `lint`, which stays at `lintSourceCommit`. Regenerating that
wholesale mixes a re-measurement into a port.

**Run it at a commit whose Go matches the law you are pinning.** The collision
cases include `enable: false` and absent-`enable` declarations, which collide
under Go before hadron-cli#676 and do not after (cor:agt:030:06,
D-2026-09-23-C). Generated at an older commit, the file would pin the retired
rule, and the TypeScript side would red against it. That is the gate working,
but it is the wrong fix.
